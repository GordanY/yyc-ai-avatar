03 / Large language model

下一句，
可能是甚麼？

LLM 會利用上下文，逐步預測並生成接下來的內容。

有點像手機的自動完成，但能處理更長、更複雜的語言情境。

看起來流暢，不代表內容一定正確。LLM 可能生成不存在的事實，仍需查證。

互動示意 · 預設例句，非即時 AI

情境：今天早上，我要去上學。

I go to school ⋯

先猜一猜，再按按鈕。換一個情境，可能的接續也會改變。

04 / Token & context

模型讀的，是一小塊一小塊的文字。

Token 是模型處理文字的單位；Context 是模型這次生成回答時可參考的內容。

已提供的內容 · Context接下來生成 · Output

圖中的分塊只用來解釋概念，並非實際 tokenizer 的切分結果。不同模型的切分方式不同；一個中文字或英文單字，不一定等於一個 token。

實際聊天時，角色設定、背景知識、你的提問及保留的對話紀錄，都會佔用上下文。

06 / Rules vs generation

同一個意思，換個問法呢？

比較「固定規則式聊天機器人」與「LLM 角色」如何處理提問。

RULE-BASED · 固定腳本示例

先寫好規則，再配對答案。

你好，歡迎使用。請輸入關鍵字：「生平」或「事蹟」。

按預設關鍵字及流程回覆；遇到規則以外的問法，這個示例便無法配對。

LLM-BASED · 岳飛角色示例

結合設定與語境，生成回應。

你好，我是以岳飛為藍本的歷史學習角色。你想談談歷史，還是學習上的挑戰？

回覆較靈活，也可能出錯。一次聊天不等於模型被重新訓練，外觀也不會保證史實正確。

兩邊均為預先撰寫的教學示例，沒有呼叫 AI。此處只比較兩種設計，不代表所有聊天機器人的能力。

07 / Research before role-play

讓數字人有根據，也有分寸。

蒐集人物資料、整理報告時，分清「史實」「故事」與「角色設定」。以下兩句，應如何標示？

資料 A

岳飛是南宋前期的重要軍事將領。

平台範本根據博物館資料整理的人物背景。

資料 B

回答中學生時，要耐心、簡明，並鼓勵他們。

你希望數字人採用的說話方式。

「岳母刺字」等敘事有不同來源與後世演繹。小說、影視情節及 AI 對話，都不能直接當作已確認的史實。

兩個連結均在新分頁開啟。API 文件是唯讀參考；跟隨老師指示使用課堂金鑰。

先連接，再對話。在平台設定欄底部「連接你的數字人」輸入 OpenRouter API 金鑰，按「連接」，等待驗證成功。金鑰只留在該頁記憶體，重新載入須再輸入。

記得比較，也記得查證。每次輸入上限為 200 字／詞，每分頁課堂提問上限為 50 次。更新角色會清空對話，提問次數會保留。重要史實請查證來源。
